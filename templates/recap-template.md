# Recap Template

Template for executive summary documents generated by `/meridian-recap`. Clear language, no technical jargon, aimed at the whole team.

---

## Authoring rules

1. **No unexplained technical terms.** No "refactor", "PR", "async", "schema", "endpoint". If you have to mention one, translate it: "the connection between systems", "the data structure", etc.
2. **No code.** No snippets, file names, or functions.
3. **What and why, never how.** Describe the result and the motivation — not the implementation steps.
4. **The technical block is optional.** Only include it if there are concrete details useful for the technical team. If there is nothing relevant, omit it completely.
5. **Short sentences.** No nested bullets. Direct tone.

---

## Template

```markdown
---
date: YYYY-MM-DD
project: <project name>
author: <name inferred from git config or the conversation>
topic: <session topic or title>
---

# Recap: <descriptive title>

## What was done?

<2–4 sentences describing what changed or was delivered. Speak in terms of
functionality or observable behavior. No technical jargon.>

Example: "It is now possible to filter the document list by status or by topic,
which previously required reviewing everything manually."

## Why was it done?

<The motivation or need that originated the work. A problem solved,
a requested improvement, or a team decision.>

## What is the impact?

<How it affects those who use the system or the team. What improved, what was
simplified, what problem no longer exists.>

## Pending

<Optional. Only if something was left out of this session or there are clear next steps.
Omit if there is nothing relevant.>

---

<!-- TECHNICAL BLOCK: include only if there are details relevant to the technical team.
     If it doesn't apply, remove this whole section. -->

## For the technical team

<Concrete details: completed tasks, affected areas of the system, relevant
technical decisions. Technical terms may be used here.>
```
